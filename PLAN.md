# Replace Feilu and Fanqie with Wattpad and Royal Road

## Recommendation

Use **one implementation prompt** for the source switch. It delivers a working research pipeline through a project-scoped import of Wattpad and Royal Road observations. The author browses the sites, records a small sample, and the app handles the analysis. This adds a manual collection step to the current one-click flow. Use the optional second prompt if you obtain a documented feed or permission for automated collection. A provider can be added for either site independently.

## Implementation plan

1. **Define one import contract and preserve past research.** In [topic models](src/models/topic.py), use stable source keys `wattpad` and `royal_road` and reuse the existing scan/report models where practical. A snapshot should carry platform, list or tag, filters, source URL, capture time, and collection method. Each observation should carry a stable story reference or URL, title, and optional language, type, visible rank, original tags, typed metrics, and short user-written notes. Keep missing values unknown. Use separate observations for separate lists and validate bounded input, platform identifiers, and matching platform URLs before staging. Prefer a pasteable CSV template for v1, with one validated structured payload to the server. Treat URLs as provenance links. Retain saved Feilu/Fanqie/Tomato fields and Chinese aliases on read as historical data where necessary. Never translate an old score into Wattpad or Royal Road fit or relabel an old scan. Preserve existing projects and checkpoints without requiring a rescan.
2. **Wire the new sources through the project workflow.** Update [routes](src/api/routes.py), the [phase executor](src/api/phase_executor.py), [graph routing](src/graph/workflow.py) and [graph nodes](src/graph/nodes.py), and the [orchestrator](src/agents/orchestrator.py) together. Replace the global platform-keyed pending input with a project-scoped snapshot. Define submission, snapshot replacement, start, retry, restart, and cleanup behavior. A run and its retries should use the same captured input unless the user submits a replacement and intentionally applies it. Prevent duplicate starts and avoid clearing valid input on failed validation or analysis. Carry the scan through the existing confirmation → topic selection → mini-arc path. With one usable source, continue and label coverage. With zero, keep retry/import available and preserve the explicit Skip to Writing route. Retire the old collector in [scraper.py](src/utils/scraper.py) after checking its callers, remove the v1 automatic-scan UI, and make the old API route return an actionable migration response.
3. **Update the market analysis and downstream generation.** In [Topic Scout](src/agents/topic_scout.py), assemble reports from validated input before any LLM call. Calculate counts and deduplication in code. Ask the LLM to interpret observable patterns and cite imported story references, supported by validation that discards invented references. Keep platform findings and coverage visible. Make cross-platform overlap an evidence-based finding, and keep sparse-data or generic brainstorming visibly ungrounded in market evidence. A listing and a short note can support discussion of the premise, positioning, and promised payoff. Treat actual chapter openings, pacing, and plot structure as unknown without supporting evidence. Use benchmarks to generate original concepts, titles, synopses, and opening arcs. Update the structured schemas, text fallbacks, candidate prompts, and synopsis/title endpoints. Replace Fanqie-only fit with separately evidenced Wattpad and Royal Road fit, including an unknown state. Use the existing creative scoring dimensions and score range where possible. Document how available fit contributes to the overall score, without penalizing a source for missing coverage. Drop short-video suitability as the default market requirement and rework the fallback directions for English-language serials. Pass the updated evidence and original concept into the writing brief.
4. **Update the frontend and documentation.** Change the [main page](src/frontend/index.html), [API client](src/frontend/js/api.js), [app controller](src/frontend/js/app.js), and [components](src/frontend/js/components.js). Use real source ranks when supplied, plain counts when absent, and sample sizes and dates for each list. Replace the combined “Trending Genres” chart with sampled genre counts by source. Show success, partial coverage, and recoverable errors based on validated observations rather than character counts. Carry scan coverage into topic-selection results so its retry guidance reflects the data available. Escape source text for display and treat imported notes as untrusted data in prompts. Document the input format, examples with synthetic stories, source limitations, and collection steps in the README.

## Acceptance checks

- Import synthetic Wattpad and Royal Road snapshots from the browser. Confirm the project reaches topic selection and mini-arc generation and that recommendations cite imported observations. Verify that topic titles, synopses, and the writing brief use the new research criteria.
- Run each platform alone, then try empty and malformed imports, duplicate stories across lists, missing metrics, and a failed enrichment call. Verify that the app preserves valid evidence, does not invent missing facts, and keeps the import or retry path available. Starting without research should still support Skip to Writing.
- Submit different data for two projects and interleave submission, start, and retry. Replace the existing expected-failure regression in [test_api_runtime.py](tests/test_api_runtime.py) with a passing test. Check that repeat starts and retries cannot overwrite or consume another run’s evidence. Load an old research checkpoint with legacy keys and confirm it can resume without presenting Chinese-market data as new-source evidence.
- Use synthetic fixtures and a fake LLM for automated checks. Include a fixture where the LLM returns an unrecognized story reference or makes a claim unsupported by a synopsis. Run the offline CI suite with `uv run pytest tests/ -v -k "not modelscope"`. Search runtime code and the UI for old URLs and labels. Remaining references should be confined to compatibility, migration messages, and historical material.
